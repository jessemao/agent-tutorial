## 问题与目标

- 当前问题：五个项目阶段 Skill 都需要报告 Work Item 状态、版本、未决事项和下一入口，但调用者缺少一个独立、只读、可在新会话恢复上下文的统一查询入口，只能重复读取多份文档并自行判断冲突。
- 目标结果：新增显式项目级 `work-item-status` Skill，从 Work Item 文件和 Git 证据计算当前可证明状态，输出结构稳定的可读报告，且对仓库绝对零写入。
- 成功指标：DISCOVERING、等待人工裁决、版本漂移、任务不存在和证据不完整场景均返回稳定结果；只有证据唯一时才提供下一动作；所有场景查询前后文件树、内容哈希与 Git 状态保持一致。

## 范围与非目标

### 范围

- 新增一个必须显式调用的项目级 `work-item-status` Skill 及其 `openai.yaml`。
- 在 `skills-lock.json` 登记项目来源、文件清单与内容哈希。
- 读取 README、阶段产物、人工确认和 Git，交叉核对后报告状态。
- 使用一个 Interface 级接缝验证成功、等待、冲突和失败行为。

### 非目标

- 不提供 JSON、HTTP API、持久化缓存、查询脚本或多个子命令。
- 不修正 README、不补建文档、不推进状态、不保存查询报告、不批准或代签。
- 不修改五个现有项目阶段 Skills、治理规范、Templates、第三方 Skills、课程卡、业务代码或业务测试。
- 不展开被查询任务的业务全文或附件。

## 业务规则与设计决定

| ID | 决定 | 理由 | 所有者 |
| --- | --- | --- | --- |
| DEC-01 | 入口固定为显式 `/work-item-status <work-item-id>` | 避免隐式查询与意外读取，保持调用面最小 | AI 治理/契约所有者 |
| DEC-02 | 输出为同时服务人和 Agent 的结构稳定可读文本 | 当前没有 JSON/API/缓存调用方，避免扩大 Interface | AI 治理/契约所有者 |
| DEC-03 | README 是导航入口，阶段产物、人工确认与 Git 是交叉证据 | 单一字段不足以证明 Workflow 状态 | AI 治理所有者、开发负责人 |
| DEC-04 | 仅在证据导出唯一动作时返回下一动作；冲突或错误不给可执行入口 | 防止跨越人工关口或从矛盾证据猜测 | AI 治理/契约所有者 |
| DEC-05 | 固定四类错误：`WORK_ITEM_NOT_FOUND`、`WORK_ITEM_STATUS_INCOMPLETE`、`WORK_ITEM_STATUS_CONFLICT`、`WORK_ITEM_EVIDENCE_BLOCKED` | 让失败可识别、可验证且不伪装成状态 | AI 治理所有者、开发负责人 |
| DEC-06 | 对仓库绝对零写入 | 查询不能改变被查询事实或留下隐式副作用 | AI 治理所有者 |
| DEC-07 | 负责人未具名但证据一致时，下一动作是由讲师/交付负责人指定角色 | 缺人不等于版本冲突，Agent 也不得代签 | AI 治理所有者、交付负责人 |
| DEC-08 | 采用一个纵向切片，不拆 Tickets、不新增脚本 | 一个 Interface 足以独立验收，拆分只会增加浅层协调 | 开发负责人、AI 治理所有者 |

## 用户旅程与交互决定

- 进入与前置数据：调用者提供已有 Work Item ID；仓库中相应目录和 Git 必须可读取。
- 一次操作的完整步骤：显式调用 → 定位任务 → 读取导航及阶段证据 → 核对 Git → 推导状态和唯一动作 → 返回报告或稳定错误 → 停止。
- 字段显示、可编辑/只读/可选择状态及允许值：唯一输入是 Work Item ID；所有仓库证据只读；输出字段不可由调用者覆盖。
- 业务文字与内部标识映射：输入 ID 映射到 `docs/work-items/<id>/`；错误使用稳定标识，报告保留人类可读说明。
- 系统生成标识、连续操作、重试与冲突：不生成新任务 ID；相同证据重复查询得到相同语义；证据变化后重新计算；冲突不任选来源。
- 成功、失败及上一次有效结果的页面行为：本任务无业务页面；成功返回完整摘要，失败返回错误、证据和停止原因；任何结果都不改变上一次有效仓库状态。
- 列表、查询、筛选、刷新或重新进入后的可见性：不提供列表或缓存；新会话用相同命令从仓库重新恢复。
- 所依赖通用能力的归属：Workflow、Templates、五个阶段 Skills 与 Git 事实属于代码起点；`work-item-status` 属于本次需求。

## 接口、数据与事务

- API/UI 契约：不新增 HTTP/UI；新增一个项目 Skill 命令 Interface，详细字段见 `interface.md`。
- 数据与状态：只读取版本化文档和 Git；不创建、更新或删除任何仓库对象。
- 事务、幂等和并发：查询没有写事务；重复调用只读。读取期间发现版本漂移或来源冲突时返回冲突，不输出可执行入口。
- Module 与所有权：`work-item-status` 是 AI 治理层的深 Module；外部 Seam 是单一命令，文件读取、核对、状态推导和渲染均隐藏在 Implementation 内。

## 风险与回滚

- 风险：文档状态与真实阶段冲突；下一动作映射遗漏人工关口；查询意外写入；输出膨胀成业务全文；把缺少具名负责人误判为冲突。
- 回滚方式：删除新增 `.agents/skills/work-item-status/` 并撤销 `skills-lock.json` 对应登记；既有五阶段 Skills 和业务代码不受影响。
