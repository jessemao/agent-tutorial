## 问题与目标

- 当前问题：T01～T04 重复使用相同的读取顺序、模板、阶段写入权限、停止条件和人工交接。T01 为教学目的手写长 Prompt，T02～T04 使用多个短命令，但尚无统一的五阶段项目入口；继续复制会导致不同 Agent 和任务逐渐遗漏字段、越过停止点或混淆角色。
- 目标结果：提供 `work-item-start`、`work-item-discover`、`work-item-execute`、`work-item-review`、`work-item-decision` 五个显式调用的项目级薄编排 Skills。它们复用现有 Templates、AI Hero/参考 Skills 和门禁，只固定项目治理，不复制专业方法或任务答案。
- 成功指标：五个 Skill 均可独立安装、验证和回退；`work-item-start` 先通过 T01/T02、两个独立会话和成功/失败路径的深度验证；其余四个随后通过逐项门禁；最终五段短命令链可执行，并稳定停在对应人工关口。

## 范围与非目标

### 范围

- 在项目 `.agents/skills/` 下新增五个目标 Skill，每个包含 `SKILL.md` 与 `agents/openai.yaml`，仅按必要性增加同目录资源。
- 五个 Skill 分别治理建档、发现、实施、评审和人工决定记录，使用统一的输入解析、产物路由、阶段停止和下一入口表达。
- 复用 `docs/ai-governance/templates/`、现有 AI Hero/参考 Skills、`skills-lock.json`、`validate-t05-skills.sh` 和 `validate-ai-governance.sh`。
- 通过五张纵向 Tickets 按 `start → discover → execute → review → decision` 顺序逐个实施。
- 保存逐 Skill 静态门禁、行为验证、跨会话隔离和完整链路证据。

### 非目标

- 不修改任何第三方 Skill 的内容或哈希，不复制其完整专业方法。
- 不改变 T01 的手写 Prompt 教学方式；T01 只作为重复机制和行为验证样本。
- 不修改仓储业务代码、业务 API/UI、数据库、事务或 T01～T04 的业务规则和答案。
- 不创建能自动批准需求、范围、Findings、测试、QA、业务验收、MR/PR 或合并的全能 Skill。
- 不用门禁脚本替代语义评审或人工放行。

## 用户旅程与交互决定

- 进入与前置数据：讲师从 `s2-t05-start` 创建小组分支；用户在新会话显式输入一个阶段命令和 Work Item ID，并提供该阶段无法从仓库获得的事实或人工决定。
- 一次操作的完整步骤：解析 ID → 定位任务卡和 Work Item → 判断当前状态 → 按固定顺序读取 → 调用当前阶段专业能力 → 只写允许产物 → 执行适用门禁 → 报告实际产物、版本、停止原因、待确认项和下一入口 → 停止。
- 字段显示、可编辑/只读/可选择状态及允许值：Work Item ID 和阶段必要变量由人输入；仓库已有事实由 Agent 读取；已批准内容只读；未知人员和结论保持待确认；状态只允许按 Workflow 推进。
- 业务文字与内部标识映射：用户使用 `Txx-Gxx` Work Item ID；Skill 将其映射到 `docs/work-items/<id>/` 和唯一 Txx 学员任务卡，不暴露或写死历史业务标识。
- 系统生成标识、连续操作、重试与冲突：Skill 不替用户生成正式 Work Item ID；重复调用必须先检查已有产物，禁止覆盖或重复签署；材料补齐后允许从同一阶段重试，版本变化必须重新核对。
- 成功、失败及上一次有效结果的页面行为：本任务无业务页面。成功时返回产物、Git/对象版本和下一入口；失败时保留上一次有效产物，返回明确停止原因和责任人，不伪造后续状态。
- 列表、查询、筛选、刷新或重新进入后的可见性：通过 Work Item 文件树、README 状态和 Git 版本恢复；新会话不得依赖旧聊天记忆，应从仓库重新读取。
- 所依赖通用能力的归属：Templates、现有 AI Hero/参考 Skills 和治理门禁属于代码起点；五个编排 Skills 属于本次需求；T01～T04 业务事实属于各自 Work Item，不迁入 Skill。

## 接口、数据与事务

- API/UI 契约：新增五个显式 Skill 命令契约；不新增或修改 HTTP/UI 接口。详细输入、输出和错误语义见 `interface.md`。
- 数据与状态：只读仓库上下文并按阶段写入 Work Item 文档、项目 Skill 文件和锁文件；不修改业务数据。状态必须遵循 Workflow，不因脚本 PASS 自动进入批准或接受状态。
- 事务、幂等和并发：文件写入前验证路径和版本；已存在产物按当前阶段契约处理，不覆盖其他 Work Item。并发检测到目录、文件或 Git 版本变化时停止，由人决定重试或合并。
- Module 与所有权：五个 Skill 归项目 AI 治理层；专业 Skills 保持原所有权；业务 Module 不在范围内。Skill 契约由 AI 治理所有者确认，实施范围由开发负责人批准。

## 风险与回滚

- 风险：五个 Skill 职责重叠；项目编排复制 AI Hero 方法；历史业务答案泄漏；隐式调用越过人工关口；门禁绿被误认为批准；新会话恢复依赖旧聊天；测试、QA 和业务结论混写。
- 回滚方式：每张 Ticket 独立提交和验证；当前 Skill 失败时回退该 Ticket 的项目 Skill 目录及对应锁文件登记，不回退已验证的前序 Skill，不修改第三方内容。整体回滚点为 `add14f73bf857604e5f738fe35111ab4ef1b3e05`。
