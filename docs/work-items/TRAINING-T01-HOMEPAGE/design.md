## 问题与设计目标

- 要解决的能力缺口：缺少学员可点击、讲师可观察的 T01 业务入口。
- 必须保持的行为：后端 API、故障和修复前后的数据语义不变。
- 非目标：前端工程化、通用管理后台、登录鉴权和业务规则上移。

## 现状与约束

- 相关 Module：`training-server` 静态资源；调用既有 `business-wms` Controller。
- 现有数据、事务、并发和异常语义：全部由后端保持。
- 不可修改的边界：公开 API、Repository、`InventoryOperations`、T01 业务代码。

## 方案

- 责任和依赖方向：`index.html + styles.css + app.js` 由 Spring Boot 提供；JS 通过同源 HTTP 调用已有 API。
- 页面结构：真实 WMS 管理后台壳层、出库订单列表、取消确认弹窗和库存明细列表；不显示培训步骤、答案提示或 API 调试控制台。
- 数据与状态变化：浏览器只保存本次演示 ID 和 API 返回值。
- 事务、幂等、锁顺序与并发：不变更，每次演示使用独立键。
- 异常与失败后最终状态：页面停止后续步骤，展示后端错误码，不伪装成功。
- 创建和预占是后端已定义的两个独立状态迁移；页面串行执行但不声称原子性，预占失败时保留 `CREATED` 单据并停止。
- 可观测性与回滚：显示每次 HTTP 方法、路径、状态和可展开 JSON。

## 备选方案与取舍

| 方案 | 优点 | 代价/风险 | 结论 |
| --- | --- | --- | --- |
| 引入 React/Vue | 更易扩展多页 | 增加构建链和课堂依赖 | 不选，超出当前需求 |
| 静态 HTML/CSS/JS 复现 `open-wms` 页面结构 | 零新依赖，容器启动即用，业务语境真实 | 不具备完整前端框架能力 | 采用 |
| 只保留单测 | 实施最少 | 不能直观演示人工验收 | 不选 |

## 测试接缝

| 设计决定 | 验证方式 | 失败信号 |
| --- | --- | --- |
| `/` 为课堂入口 | MockMvc 访问根路径和 `index.html` | 404 或缺少主操作按钮 |
| 同一页面区分修复前后 | 真实浏览器运行完整流程 | 未显示单据和库存最终值 |
| 可重复演示 | 换数据后再运行 | 单号/幂等冲突 |
