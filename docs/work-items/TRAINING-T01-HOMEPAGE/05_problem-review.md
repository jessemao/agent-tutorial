# 05 Problem Review：South Admin React 前端

## 本轮要解决的问题

- 前一版虽然像 WMS，但仍是手写 HTML/CSS/JavaScript，无法体现 UI 团队统一框架和组件复用方式。
- 用户指定 `southliu/south-admin-react` 后，目标从“参考真实页面”升级为“使用统一前端技术栈和管理后台组件”。

## 处理结果

- 将前端源码与 Spring 静态产物分开，建立可重复的 Docker 构建入口。
- 使用 React、TypeScript、Vite 和 Ant Design 重构壳层与业务页面。
- 保留 South Admin 的管理后台交互语言，同时裁掉与课堂无关的鉴权和通用系统模块。
- 将第三方提交、许可证、版本、安全补丁和锁文件纳入来源登记。

## 新发现的环境问题

- Docker 磁盘不足会在镜像层注册阶段失败，表现与源码构建失败不同。
- 恢复动作应先确认磁盘与可回收对象，只清理悬空层，再重试同一构建命令。
- 不应以切换到本机 Node 规避课堂 Docker 约束，否则验证环境会发生变化。

## 后续门禁

- UI 框架需求必须在 Spec 中明确“采用哪些能力、裁掉哪些能力、源码与产物放在哪里”。
- 每次前端构建都必须使用锁文件，并同时运行依赖审计和 TypeScript 构建。
- 依赖升级必须记录是否为功能升级还是安全补丁，不能静默跟随最新版本。
