## 问题与目标

- 当前问题：已有页面是自创的培训控制台，不是仓储人员实际使用的业务页面，无法形成真实业务操作感。
- 目标结果：学员在真实 WMS 风格的出库订单列表中准备并取消单据，再到库存明细页验收最终状态。
- 成功指标：初始分支显示 `CANCELLED / 4 / 6` 并判定失败；修复分支显示 `CANCELLED / 10 / 0` 并判定通过。

## 范围与非目标

### 范围

- Spring Boot 同源静态首页，无额外前端依赖。
- 采用 `open-wms` 的出库订单和库存明细页面作为视觉与信息架构参照。
- 出库订单列表、筛选区、行选择、取消确认、刷新和库存明细切换。
- “新增演示单”只负责调用现有 API 准备一条 `RESERVED` 单据，取消后通过公开查询 API 刷新单据与库存。
- 每次生成新的 SKU、单号和幂等键，允许同一进程重复演示。

### 非目标

- 不建设完整仓储前端，不增加登录、角色、菜单权限、路由鉴权或生产 UI 框架。
- 不复制第三方前端源码或图片资源；只参考已登记的公开页面结构与仓储术语。
- 不改变 API、业务状态、库存规则、事务或数据库。
- 不以页面判定替代后端测试和双轴评审。

## 业务规则与设计决定

| ID | 决定 | 理由 | 所有者 |
| --- | --- | --- | --- |
| DEC-01 | 页面只调用现有公开 API，不承载库存写逻辑 | 保持 `training-server` 组合根边界 | 技术 |
| DEC-02 | 验收同时查询单据和库存 | 防止“单据成功”掩盖库存错误 | QA |
| DEC-03 | 相同页面跨 T01 起始和答案分支使用 | 同一验收入口能区分修复前后 | 课程 |
| DEC-04 | 页面采用真实 WMS 列表而非培训步骤面板 | 让学员从业务操作和最终数据发现故障 | UI/课程 |
| DEC-05 | 不实现鉴权，只保留后端审计所需固定操作人头 | 避免课堂环境复杂化 | 技术/课程 |

## 接口、数据与事务

- API/UI 契约：只使用已有入库、出库创建、预占、取消、单据查询和库存查询。
- 数据与状态：演示数据为虚构值，页面不直接存取数据库。
- 事务、幂等和并发：沿用后端现有语义；页面为每次用户意图生成稳定幂等键。
- Module 与所有权：只修改 `training-server` 课程组合根。
