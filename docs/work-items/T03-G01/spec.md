## 问题与目标

- 当前问题：系统已有单库位库存变更、锁、幂等、流水和审计能力，但没有面向调用方和课堂 UI 的原子库内移库 Interface。
- 目标结果：仓库操作人可通过单一 HTTP/UI 操作，把同一仓库内某 SKU 的正整数可用量从源库位原子移到不同的目标库位。
- 成功指标：成功请求仅改变两端可用量，保持占用量不变，生成两条流水和一次审计；重放不重复改数据；任一失败不留部分结果；反向并发不死锁且库存不变式成立。

## 范围与非目标

### 范围

- 在 `InventoryOperations` 增加单一原子移库 Interface，隐藏两端锁定、余额变更、幂等、流水和审计。
- 在 `/api/wms/inventory` 下增加单一移库 HTTP 入口，复用现有统一响应和错误语义。
- 在课堂 UI 启用“移库作业”，自动生成移库单号，通过移库 HTTP Interface 展示成功后两端余额和失败反馈，并从既有双流水查询已完成任务。
- 增加公开 Interface 端到端验收、事务回滚、幂等、并发、流水/审计及现有库存回归验证。
- 在文档中澄清 `docs/architecture.md` 的 `transfer` 是 T03 目标状态，不是基线已有能力。

### 非目标

- 跨仓调拨或跨 SKU 移库。
- 移动占用库存，或改变现有预占/出库语义。
- 移库单独立数据表、独立状态机、异步审批、撤销或批量移库；任务列表只读复用既有双流水。
- 库位停用/删除流程、数据迁移或生产级事务审计存储。
- 修改 `platform-*`、数据库结构、Module 依赖、Maven/npm 依赖或现有公开契约。

## 业务规则与设计决定

| ID | 决定 | 理由 | 所有者 |
| --- | --- | --- | --- |
| DEC-01 | “库内移库”仅指同一仓库内两个不同库位之间的库存移动 | 跨仓属于仓间调拨，需要另一套状态和责任语义 | 业务所有者 |
| DEC-02 | 只移动可用量，两端占用量不变 | 占用量已与出库流程关联，不在本任务范围 | 业务所有者 |
| DEC-03 | 源/目标库位必须存在、启用、属于请求仓库且不得相同；目标 SKU 余额可自动建立 | 拒绝无效位置，同时不要求预先制造空余额 | 业务所有者 |
| DEC-04 | 数量必须为正整数，可等于全部源可用量；不足、溢出或任一失败整体回滚 | 保持非负库存并禁止静默部分移库 | 业务所有者 |
| DEC-05 | 每次请求携带移库单号和幂等键；同键同载荷返回首次快照且不重复写入，同键不同载荷冲突 | 区分安全重放与载荷冲突 | 业务所有者、UI/契约所有者 |
| DEC-06 | 成功响应返回移库单号和源/目标操作后余额 | 便于调用方和 UI 验证结果，也支持首次快照重放 | UI/契约所有者 |
| DEC-07 | 成功首次执行生成 `TRANSFER_OUT` 和 `TRANSFER_IN` 两条流水及一次 `TRANSFER` 审计；失败/重放不新增 | 分别追溯两端余额，复用现有数据结构 | 业务所有者 |
| DEC-08 | 在单一 `InventoryOperations.transfer` 事务中，按库位 ID 升序锁定两个库位和已有余额 | 保证两端原子性，并避免反向移库按相反顺序加锁 | 开发负责人 |
| DEC-09 | 在库位锁内查询幂等流水；如库位日后停用/删除，重放可优先返回库位错误 | 优先保证并发请求读取同一提交时点的幂等记录 | 开发负责人、UI/契约所有者 |
| DEC-10 | 实现仅限 `business-wms` 库存领域/Web Adapter、`training-server` 课堂 UI/集成测试和相关架构文档 | 当前能力已足够，无需扩展平台、数据库或依赖 | 开发负责人/架构所有者 |
| DEC-11 | 当前审计只通过同步日志 Adapter 调用一次，不声称其可与数库提交原子回滚 | 这是不修改平台和数据库边界下的已批准限制 | 开发负责人 |
| DEC-12 | UI 自动生成移库单号和幂等键；已完成任务列表由成对的 `TRANSFER_OUT`/`TRANSFER_IN` 流水只读生成 | 避免普通操作误复用幂等键，同时不新增移库表或状态机 | UI/契约所有者 |

## 用户旅程与交互决定

- 操作人从“移库作业”进入，使用 SKU `303`，以文字库位填写源 `A01-01-01`、目标 `A01-01-02` 和数量；页面不暴露库位数据库 ID。
- 源/目标库位为可编辑文字输入，允许操作人填写不存在的库位验证失败契约；当前数据中只有 `A01-01-01`、`A01-01-02` 有效。
- 移库单号和幂等键由页面为每次普通提交自动生成，不要求人工输入。显式安全重放和冲突载荷通过 API 自动化测试验证。
- 成功后页面显示移库单号、SKU、源/目标库位、数量和两端余额；失败时显示服务端错误，已成功任务仍可从列表查询。
- 打开或刷新页面时从既有双流水加载已完成任务列表；列表不是独立状态机，不增加移库任务表。
- SKU `303` 的期初库存、两个有效库位以及库存明细按单个/全部库位查询属于代码起点；移库输入、动作、结果和任务列表属于本 Work Item。

## 接口、数据与事务

- API/UI 契约：`POST /api/wms/inventory/transfer` 执行移库，`GET /api/wms/inventory/transfers` 从既有流水读取已完成任务。课堂 UI 自动生成 `idempotencyKey`/`transferNo`，展示成功详情、错误和可刷新任务列表。完整字段和错误矩阵以已批准 `interface.md` 为准。
- 数据与状态：不新增业务单表或状态机。源可用量减少、目标可用量增加，两端占用量不变；目标余额可在锁保护下以零起点创建。两条流水保存首次操作后余额快照。
- 事务、幂等和并发：单事务按库位 ID 升序锁定库位，再在同一顺序下锁定已有余额。锁内查询两条幂等流水：两条均匹配时安全重放，只有一条或载荷不匹配时冲突。新请求校验后更新两端、写入双流水并调用一次审计；任一数据库异常回滚整个事务。
- Module 与所有权：`business-wms` 拥有全部业务语义和 HTTP Adapter；`training-server` 仅组装 UI 与集成测试；`platform-*` 仅被复用而不修改。

## 风险与回滚

- 风险：双余额更新可能产生部分成功；反向并发可能死锁；目标空余额可能并发创建；重放可能重复扣加或返回错误快照；溢出可能破坏总量；UI 可能和 HTTP 契约漂移。通过单事务、稳定锁顺序、双流水幂等快照、溢出检查和公开 Interface 测试控制。
- 剩余风险：课堂 `AuditPublisher` 是同步日志 Adapter，不是事务性审计表；因此只验证已知业务失败/安全重放不调用审计，不声称审计日志与数据库提交可原子回滚。H2 不能单独证明 MySQL 锁行为，需要课程 MySQL Profile 结果。
- 回滚方式：回退本 Work Item 的 UI、HTTP Adapter、Module Interface、Implementation、测试和架构文档 Diff；不删除或改写已有库存记录。已执行业务移库若需逆向操作，必须作为新的受审业务请求，不通过代码回滚修改历史。
