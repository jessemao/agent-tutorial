## 交付行为

用户从库存盘点页面通过仓库、SKU 和库位的业务编码/名称选择同一仓库内的一条或多条库存维度，创建由系统生成单号的盘点草稿。系统记录每条创建账面快照并原子占用活动范围；有效但没有余额的维度按零处理。用户可在列表和详情中重新查看草稿并刷新恢复。

创建请求只要包含重复明细、异仓/失效主数据或已被活动盘点占用的明细，就整单失败并返回结构化冲突对象，不产生部分盘点或部分范围占用。

## 修改边界

- 允许修改：`business-wms` 的最小 SKU 主数据、盘点创建/查询深 Module、活动范围和创建幂等持久化、盘点/主数据 HTTP Adapter；`training-server` 的 SKU 演示数据、盘点列表/创建/详情页面与对应集成测试。
- 禁止修改：平台 Modules、现有入库/出库/移库/余额公开行为、库存调整实现、审核状态、Tickets 02—05 的业务行为、治理规范和第三方 Skills。
- Module `AGENTS.md`：必须遵守根规则、`business-wms/AGENTS.md` 与 `training-server/AGENTS.md`。

## 验收条件

- [ ] AC-01：创建同仓多条唯一明细后，系统生成唯一业务单号、状态为 `DRAFT`、保存创建快照并返回仓库/SKU/库位业务文字。
- [ ] AC-02：重复、异仓、无效或活动范围冲突使整单失败；响应定位每个问题明细及冲突单号，数据库没有部分单据/明细/范围占用。
- [ ] AC-02：两个并发请求争用同一库存维度时最多一个成功；MySQL 唯一约束结果可验证。
- [ ] AC-03：有效维度无余额时创建成功，创建账面总量为零。
- [ ] AC-15：创建网络重试同键同参返回首次结果，同键异参返回幂等冲突，不重复创建。
- [ ] AC-16：列表按创建时间和 ID 稳定倒序，详情与刷新恢复已保存草稿；筛选/分页至少支持本票已存在的数据。
- [ ] 页面不暴露内部 ID，不要求用户填写盘点单号或幂等键；失败时保留选择并展示结构化错误。
