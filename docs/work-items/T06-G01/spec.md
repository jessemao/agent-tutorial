## 问题与目标

- 当前问题：仓库现场物理数量可能与系统库存不同，当前系统没有盘点单、实盘录入、审核、差异确认、库存校准、查询或课堂操作页面；现有库存写入口只表达正数增量，不能安全表达物理实盘总量和负差异。
- 目标结果：用户可以在一个仓库内创建多明细盘点单，录入物理实盘总量，经独立审核和必要的最新差异二次确认后，原子修正可用库存，同时保持占用量、流水、审计和盘点状态一致。
- 成功指标：完整页面/API 旅程可用；零值、正负差异、无余额、异常状态、重复请求、范围冲突、并发变化和事务失败都有明确结果；失败不留下部分库存、流水或批准状态；既有库存业务保持兼容。

## 范围与非目标

### 范围

- 一个盘点单只属于一个仓库，可包含一条或多条不同的 `SKU + 仓库 + 库位` 明细。
- `DRAFT`、`SUBMITTED`、`REJECTED`、`APPROVED`、`CANCELLED` 生命周期及创建、保存、提交、重新编辑、驳回、取消、审核。
- 物理实盘总量、创建/提交快照、审核时最新账面复核、差异二次确认和最终余额快照。
- 同一库存维度只能被一个活动盘点占用；多明细动作全部成功或全部失败。
- 所有写动作的操作者、幂等、文档版本、状态校验和审计。
- 列表、详情、筛选、刷新恢复、课堂页面及所需业务值选择。
- 最小 SKU 主数据、盘点 Module Interface、库存批量校准 Interface、盘点持久化及业务本地结构化冲突响应。

### 非目标

- 跨仓盘点、库存冻结、部分审核、跳过失败明细、已批准单反审。
- 修改现有入库、出库、移库、余额查询规则或 HTTP 契约。
- 修改平台 Module 或平台统一响应/异常实现。
- 完整登录/RBAC；本次只要求身份可追溯与禁止自审。
- PDA、扫码、批次/序列号、附件、物理删除、自动归档、保留期限。
- 通用工作流、任意库存调整、远程主数据、Redis、MQ、分布式事务或新第三方依赖。
- 自动反转已经批准形成的库存事实。

## 用户旅程与交互决定

- 进入与前置数据：从“库存盘点”进入列表；系统提供启用仓库、SKU 和库位的业务值选择。有效维度可以没有余额。
- 完整步骤：创建同仓多明细盘点 → 草稿录入并保存 → 补齐后提交 → 不同操作者审核 → 若账面变化则查看最新差异并确认 → 查看批准结果；待审核也可驳回/取消。
- 字段控制：草稿可增删明细、修改 nullable 实盘和备注；实盘为非负整数且允许零；已提交只读；驳回后经“重新编辑”恢复可写；终态只读。
- 业务文字：页面显示盘点单号、仓库 code/name、SKU code/name、库位 code/name；内部 ID 仅由 Adapter 提交。
- 技术标识：系统生成盘点单号；页面生成幂等键，新动作新键、网络重试复用；页面维护版本和 opaque token，用户不输入或解析。
- 成功/失败：成功用完整服务端详情替换页面模型；失败保留当前表单输入并展示服务端有效版本和结构化错误；差异变化展示最新逐行差异。
- 查询与恢复：列表稳定倒序，支持单号、仓库、状态筛选和受限分页；详情恢复已保存状态、操作者、时间、原因和数量快照；未保存本地输入不承诺恢复。
- 能力归属：现有操作者、审计、幂等判断、响应和异常映射属于起点；最小 SKU 及业务值选择属于本需求；完整鉴权属于独立 Work Item。

## 接口、数据与事务

- HTTP/UI：新增列表、创建、详情、完整草稿保存、统一状态转换、审核，以及仓库/SKU/库位选择查询。差异变化使用业务本地结构化 409，携最新详情/token。
- Module Interface：盘点暴露 `create`、`saveDraft`、`transition`、`approve`、`get`、`list`；库存新增批量 `reconcileCount`；Controller 只映射输入输出。
- 数据：盘点聚合保存状态/版本/人员/时间/原因；明细保存创建、提交、审核前和批准后快照；活动范围表强制唯一；动作回执保存指纹和首次领域结果；preview 保存确认事实；SKU 保存 ID/code/name/enabled。
- 事务：成功审核时盘点、全部余额、非零差异流水、范围释放、回执和成功审计同事务提交；任一失败整批回滚。
- 失败记录：内层审核回滚后，外层 Facade 只可在独立短事务保存稳定失败分类并保持 `SUBMITTED`；差异变化另存 preview/token 与冲突审计；不得保存堆栈或伪装成功回执。
- 锁顺序：先盘点聚合，再按库位 ID 升序锁全部库位，再按 `(locationId, skuId)` 锁定/创建余额；沿用现有“库位先于余额”。
- 幂等/版本：动作类型+幂等键唯一，规范业务载荷生成指纹；创建外核对预期版本；token 绑定盘点 ID/版本、规范维度及审核读取的余额事实。
- 所有权：盘点、SKU、HTTP、库存扩展在 `business-wms`；课堂页、演示数据和端到端测试在 `training-server`；平台 Module 禁止修改。

## 测试决定

- 只验证公开行为和最终状态；不直接调用 Repository、不改数据库构造成功、不 Mock 核心盘点/库存行为。
- 最高 Seam：规则用 `InventoryCountOperations`，HTTP/UI 用 MockMvc/课堂页面，跨业务并发用 `training-server` 公开入口。
- H2 覆盖快速行为；活动范围、锁、确认窗口、死锁和并发不变式必须补 MySQL Profile。
- 复用现有库存回归、回滚、幂等、移库原子性和 MySQL 并发测试形态，但不复制其业务答案。
- 固定顺序：最小 Red/Green → Module 回归 → MySQL 专项 → `mvn clean verify`；真实结果留待实施验证记录。
- 测试工程师独立设计功能测试；QA 只审核流程、追溯、覆盖、证据和缺陷闭环。

## 风险与回滚

- 风险：多明细锁与既有库存竞争；H2/MySQL 约束差异；首次结果快照复杂度；业务本地 409；SKU 扩围；独立失败事务掩盖主错误；数量极值。
- 控制：统一锁序、显式范围表、MySQL 并发验证、领域结果快照、平台只读、稳定失败类别、全量最终状态断言。
- 回滚：停止入口，回滚页面/API、盘点/SKU 专属表和库存 Interface 扩展；不迁移既有库存表。已批准产生的库存事实由业务所有者决定后续纠正，不自动反转。
- 回滚点：`b09d8e69db9403e891bdc2562d3742487d3cdc23`；后续每个纵向 Ticket 另设独立回退边界。
