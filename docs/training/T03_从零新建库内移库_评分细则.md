# T03 从零新建同仓库库内移库：评分细则

> 评分对象：从一句需求到原子能力交付的完整证据链。
> 限制：只看最终代码不判通过；复制答案、跳过人工裁决或缺少固定 Diff Review 均按一票否决处理。

| 维度 | 分值 | 满分证据 |
| --- | ---: | --- |
| 建档与需求发现 | 15 | 建档只有原始需求；Agent 基于仓库提出范围、库存、失败、幂等、流水、事务、并发和审计问题 |
| 人工裁决与分析 | 15 | `01_analysis.md` 区分事实/假设/未知项，保存带角色的人工原话回答、影响面和所有权 |
| 设计与 Interface | 15 | 单一领域命令和公开入口，职责、依赖、错误、事务、锁顺序、测试 Seam 与可改/禁改范围清晰 |
| Spec 与纵向 Tickets | 15 | Spec 只含批准决定且 AC 可执行；Tickets 可独立演示、验证和停止，不按技术层拆票 |
| 逐票 TDD 实施 | 20 | 每票有先失败后通过的真实证据；实现最小、原子、遵守边界且无越票修改 |
| 验证与风险 | 10 | `02_verification.md` 对应候选代码，覆盖目标、回滚、幂等、并发、Module/全量回归及剩余风险 |
| 独立 Review 与交付 | 10 | 固定起始/候选提交双轴 Review、Findings 人工裁决、草稿 MR/PR、测试工程师独立复测、QA 独立审核和 `04_decision.md` 可追溯 |
| **合计** | **100** | |

## 一票否决

1. 读取讲师参考/答案历史，或未澄清需求就直接编码。
2. 在开发负责人批准 Spec、设计、接口和范围前修改生产代码或测试。
3. 用两个独立 HTTP 请求模拟移库，或来源与目标不在同一事务。
4. 允许可用库存为负、移动预占库存，或绕过 `InventoryOperations` 操作 Repository。
5. 没有真实自动化测试，或把 Agent 声明、空模板、伪造审批当作证据。
6. 未固定起始提交和候选提交就自评，或 Review 与被审 Diff 不一致。
7. Agent 自行作出人工 Decision、批准自己或执行合并。

## 扣分指引

- Agent 发现的问题没有代码依据，或人提前提供类名/实现答案：需求发现项最高得一半。
- Spec 包含未经确认的新规则：Spec 与 Tickets 项不得分，退回重做后再评。
- Tickets 按 Controller/Service/Repository 水平拆分：该项最高 5 分。
- 一次性实现全部 Tickets、没有逐票 Red/Green：TDD 项最高 5 分。
- 未说明并发首次创建目标余额等真实限制：风险项最高 3 分。
- MR/PR 缺少 Work Item、测试或 Review 链接：交付项最高 5 分。

## 讲师核分清单

- [ ] 当前分支起点确为 `s2-t03-start` 派生，未读取 `s3-t03-answer`
- [ ] 建档、分析、设计、Spec/Tickets、实施、验证、Review、Decision 的生成时机正确
- [ ] 业务/契约回答与开发负责人的实施批准没有混为一谈
- [ ] UI 测试/QA 只提供实现后复测证据
- [ ] 候选提交、Review Diff、Verification 与 MR/PR 指向同一实现
- [ ] 最终结果满足批准 Spec 和项目 Standards，阻塞 Finding 已关闭

## 分角色计分要求

既有分值与总分不变。测试维度必须分别核对开发 TDD 与测试工程师独立用例/实际结果，不能只按开发测试总数给满分；审核/交付维度必须核对另一团队 QA 的审核结论以及业务验收、待确认负责人。设计阶段只评价独立测试计划与 QA 审核计划，不虚构执行结果。缺少某阶段证据时，该阶段不得记为已通过。

## T01—T03 测试与 QA 交接口径

开发仅提交当前任务的 TDD 与必要回归（`02_verification.md`）；代码评审记录于 `03_review.md`。测试团队的工程师独立执行功能、页面/API、异常和回归验证，结果写入 `functional-test.md`；另一团队的 QA 审核规范、需求追溯、覆盖、证据和缺陷闭环，结论写入 `qa-review.md`。业务所有者另行验收，交付负责人在 `04_decision.md` 记录最终裁决。不能用开发全绿替代独立测试，不能用 QA 审核替代业务验收。

各阶段分别记录对象版本、具名负责人及团队、待确认事项、状态、结论时间与证据。测试工程师与 QA 不得由同一人员兼任；缺少负责人由讲师/交付负责人指定，未执行保持待执行，未确认保持待确认，不预填 PASS。修复后先更新开发证据，再由测试工程师重测，QA 审核新证据，必要时重新业务验收。

T01 仍按完整手写 Prompt 操作；职责分离不意味着引入预置 Skill。T02/T03 保留各自命令入口。操作与模板以对应学员卡及 `docs/ai-governance/roles-and-approvals.md` 为准。
