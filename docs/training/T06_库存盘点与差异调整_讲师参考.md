# T06 库存盘点与差异调整：讲师参考

## 设计意图

T06 不再按步骤带做，而是检查学员能否独立完成“`/grill-with-docs`→人工确认→`/to-spec`→四方评审并批准 Spec→`/to-tickets`→`/implement`→`/code-review`→Spec/Standards 双轴比对→人工交付裁决”。考核重点是库存正确性与审核证据，不是代码量。

## 信息分批投放

| 时点 | 触发条件 | 提供信息 |
| --- | --- | --- |
| 开始 | 全员 | 只提供原始需求和起始代码 |
| 需求会 | 小组已提出盘点范围、预占、冻结、审批、幂等问题 | 公布学员卡中7条训练规则 |
| 设计评审 | 小组提交影响面 | 确认仅仓储事业部和培训组范围可修改 |
| Spec 审批 | 四方结论齐备 | 生成 Spec 版本、代码固定点和哈希；冻结后不允许静默改写 |
| 实施受阻 | 交付物证明事务/幂等理解有误 | 只提示检查“审批单状态和库存调整是否同事务” |

## 标准设计

- `Stocktake` 保存盘点号、库存维度、快照总量/预占量、实盘总量、状态和审批幂等键。
- 创建为 `PENDING_APPROVAL`；审批成功后为 `APPROVED`。
- `InventoryOperations` 新增一个明确的盘点调整命令，仍作为库存变更唯一入口。
- 创建时确认库存维度存在并验证实盘总量不小于预占；审批时库存服务锁定余额、比较快照、仅更新可用量并记录 `COUNT_ADJUST`。
- 盘点审批方法与库存调整同事务；调整失败时盘点单不能变为已审批。

## AI 常见错误

- 把实盘数当作可用量，导致预占量被重复计算。
- 创建盘点单时立即调库存，绕过审批。
- 审批先改单据状态，库存调整不在同一事务。
- 只校验总量，未校验快照预占量，遗漏陈旧快照冲突。
- 对已审批单据无条件返回成功，忽略不同幂等键冲突。
- 为了新需求修改平台组件，越过事业部所有权。

## 时间建议（120 分钟）

- 0—20：`/grill-with-docs`、角色分工与需求会。
- 20—35：模型、API、事务、幂等和测试设计评审。
- 35—45：四方签署、批准 Spec，并校验清单哈希。
- 45—85：AI 辅助实施与小步测试。
- 85—105：`/code-review`、Spec 逐条比对与人工修正。
- 105—120：演示、证据矩阵、风险和复盘。
