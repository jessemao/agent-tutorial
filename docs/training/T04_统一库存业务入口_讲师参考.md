# T04 统一库存业务入口：讲师参考

> 对象：讲师/助教。状态：与 `s2-t04-start` / `s3-t04-answer` 配套。
> 投放限制：先让 Agent 报告候选、让人选择，再释放参考结构；不得一开始告诉学员删除哪些类。

## 1. 教学目标与 PPT 对应

本节对应 PPT P47～P53：P47 发布任务，P48 固定“行为不变”的重构前提，P49 Skill 发现候选，P50 锁定行为并批准设计，P51 形成 Spec 与迁移 Tickets，P52 逐票实施，P53 验证、独立 Review 与合并决定。

本任务没有功能 Bug。核心分工是：**Agent 找结构问题和迁移方案，人选择候选、批准保持行为与边界；Agent 小步迁移并举证，人决定是否交付。**

## 3. 参考候选与人工选择

起点中库存修改公开入口分散：常规动作经 `InventoryOperations`，移库经 `InventoryTransferOperations` 和 `LegacyInventoryTransferService`。期望 Agent 自己发现：

- Controller 依赖多个表达同一领域能力的入口；
- 幂等、库位校验、余额查询、流水和审计规则存在分散风险；
- 修改同一库存规则时需要跨入口同步，增加遗漏成本；
- 现有公开行为测试可以作为迁移保护网。

人工选择“统一库存公开业务入口”这一候选，拒绝全库重写、通用工作流引擎、反射分发和与当前问题无关的清理。选择必须写入 `01_analysis.md`，但不预先指定每个实现步骤。

## 4. 保持行为与参考设计

修改前应记录当前起点实际通过的行为测试数量和命令，不把“11 条”当脱离环境的口头结论。至少固定：HTTP 路径/字段、成功结果、错误码、状态、幂等、事务回滚、双流水、审计和锁顺序。

可接受参考结构：

1. `InventoryOperations` 增加稳定的 `transfer` 业务能力。
2. 移库实现归入库存领域内聚实现，继续保持原事务、幂等和锁语义。
3. Controller 只依赖 `InventoryOperations`。
4. 所有调用方迁移并搜索确认后，删除多余公开 Interface 和旧实现。

“统一 Interface”不等于“所有 Implementation 塞入一个巨型方法”。学员要比较巨型方法、机械 Helper、稳定入口+内聚实现三种方案，以 Locality、Leverage、调用者负担、规则归属、事务风险和测试位置作决定；类/方法长度只作为预警。

## 5. Tickets 与实施观察

推荐迁移顺序：

- Expand：新增稳定入口并让现有行为测试保护它，不删除旧入口。
- Migrate：按调用方切换依赖，每步保持测试全绿。
- Contract：搜索确认零旧调用后删除旧 Interface/实现，再运行完整回归。

纯重构不要求为了展示 TDD 人工制造失败；现有公开行为测试是保护网。只有发现可观察行为没有测试时，先补会失败或能锁定现状的 characterization test。任一步测试失败或行为改变，就回滚当前 Ticket，不带病进入下一票。

## 6. Review、交付与恢复

完成 `02_verification.md` 后先形成候选提交，再由新会话对固定起始/候选提交运行 `/code-review`。Spec 轴检查行为保持和目标结构，Standards 轴重点检查巨型 Service、透传层、规则漂移、依赖方向和测试弱化。人工关闭阻塞项并重新验证后才创建草稿 MR/PR；UI/QA 在实现后复测；Agent 不得替人批准或合并。

课堂未完成时保存学员分支与 Work Item，在独立干净目录使用 `s3-t04-answer` 做只读对照。答案只展示一种可接受结构，不因类名与答案不同直接扣分；以行为、边界和证据评分。

## 7. 常见错误

- 为五个稳定动作创建 `OperationType`、反射工厂和通用命令。
- 把不同动作压进一个包含大量可空字段的万能方法。
- 只增加一层一行转发的“统一 Service”，重复规则仍在原处。
- 先删除旧入口再迁调用方，导致不可回退的大 Diff。
- 修改/删除旧测试迎合新结构，丢失重构前证据。
- 看到测试全绿就宣称完成，没有搜索旧调用方或做前后行为映射。
