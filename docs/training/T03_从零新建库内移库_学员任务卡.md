# T03 从零新建同仓库库内移库：学员任务卡

## 任务定位

- 场景：从 0 新建需求
- 时长：120 分钟；课堂完成需求、设计、测试骨架和核心路径
- 起点：`s2-t03-start`，即现有仓储公共版本但不存在移库功能；新T02分批收货代码尚未同步，不作为本任务前置条件

## 业务问题

在同一仓库进行补货、库位整理或拣货位补充的场景下，仓管员需要把某个 SKU 的可用库存从来源库位移动到目标库位。现有系统只有入库和出库能力，如果用“先出库、再入库”两次操作拼接，一旦中途失败就会出现库存丢失、重复增加或流水无法对应。需要从零建立一项原子的库内移库能力，使来源扣减、目标增加、双向流水和审计一次成功或一次失败，并在库存不足、重复请求及并发操作下保持数量正确。

## 原始需求

> 支持将一个库位上的库存移动到另一个库位。

这句话不能直接用于编码。使用 AI 前必须澄清：跨仓/跨区、库存口径、部分成功、目标库位创建、幂等、流水、事务、并发和审计。

## 本次冻结规则

- 只支持同仓库、不同库位。
- 只移动可用库存，不移动预占库存。
- 来源不足时整体失败，目标库存不得增加。
- 目标无余额时自动创建。
- 相同幂等键和载荷返回原结果；冲突载荷显式拒绝。
- 生成 `TRANSFER_OUT` 和 `TRANSFER_IN` 两条流水。
- 来源、目标、流水和审计在同一事务中。
- 按库位 ID 固定顺序加锁。

## 允许和禁止

- 允许修改仓储库存领域、Web 适配器和测试。
- 可复用平台操作人和审计契约，不允许修改平台实现。
- 必须通过 `InventoryOperations` 暴露移库能力。
- 禁止用两次 HTTP 调用“出库 + 入库”拼装移库。
- 禁止先提交来源再更新目标。

## 必交付

编码前按 `docs/ai-governance/standards/architecture.md` 提交并批准结构设计，并按 `docs/ai-governance/standards/clean-code.md` 调用专项 Skills：明确移库命令的 Interface、库存规则归属、锁顺序与事务编排，检索已有库存、幂等和审计能力。禁止把查询、校验、两端更新和 Web 处理堆入一个通用方法。

- [ ] 澄清问题及业务裁决
- [ ] 领域命令、返回结果和 API 契约
- [ ] 影响面与所有权矩阵
- [ ] 职责/Interface/依赖/复用已批准设计及逐条结构比对
- [ ] 经审核的 AI 实施计划
- [ ] 正常、幂等、来源不足、同库位、非法库位和并发测试设计
- [ ] 代码、测试报告、人工评审和剩余风险

## 最低验收

1. 来源 10、移动 6 后，来源可用 4、目标可用 6。
2. 相同请求重试后数值不再变化。
3. 来源只有 3、请求移动 5 时，来源仍为 3、目标仍为 0。
4. 原有入库、出库、取消、幂等和权限测试全部通过。
