# T02 调整入库分批收货规则：讲师参考

> 代码状态：仅完成非代码材料。旧 T02 标签仍对应“取消出库规则”，禁止作为本任务答案展示。

## 设计意图

本任务用独立的入库场景训练“需求调整”：保留旧行为和兼容性事实，审核新增规则，批准 Spec 后再让 AI 修改代码。

## 建议澄清结论

| 疑点 | 训练结论 |
| --- | --- |
| 数量语义 | 请求传本次实收量，不传累计量 |
| 状态 | 未收为原状态；部分收货为 `PARTIALLY_RECEIVED`；累计等于计划量为 `RECEIVED` |
| 超收 | 本次数量超过剩余量时整体拒绝，不截断、不写库存 |
| 原子性 | 入库累计量、状态、库存流水和审计在同一事务中 |
| 幂等 | 同键同载荷重放首次结果；同键不同数量冲突 |
| 并发 | 锁定入库单及相关库存，最终累计量不得超过计划量 |
| 兼容性 | 旧一次性收货客户端必须有兼容或迁移方案；新状态需 UI 审核 |

## 最小验收矩阵

1. 计划 10，首次收 4：累计 4，状态 `PARTIALLY_RECEIVED`，库存增加 4。
2. 再收 6：累计 10，状态 `RECEIVED`，库存再增加 6。
3. 已累计 4 时再收 7：拒绝，累计量、状态和库存不变。
4. 数量为 0 或负数：入参边界拒绝。
5. 相同幂等键和相同数量重试：不重复增加库存。
6. 相同键但数量不同：显式幂等冲突。
7. 库存写入失败：入库累计量与状态共同回滚。
8. 并发收最后一批：最多一个请求成功，最终不超收。

## 讲师观察点

- 学员是否先区分旧行为、新行为、不变行为和未知项。
- 是否明确“本次数量”而不是让 AI 自行选择数量语义。
- 是否识别新增状态对 UI、API 和报表的影响。
- 是否把超收处理成整体拒绝，而不是静默截断。
- 是否覆盖事务、幂等、并发和旧客户端兼容。
