# T01 取消出库未释放库存：学员任务卡

> 类型：Bug 修复。状态：可实操。对象：学员。  
> 权威输入：本任务卡、讲师分配的 `group-demo/t01` 网页教学工作目录、根及相关 Module 的 `AGENTS.md`。  
> 限制：不得提前读取讲师参考或答案标签；人工批准根因和修复范围前不得修改业务代码。

## 1. 任务定位

- 研发场景：修改 Bug
- 业务模块：出库单、库存
- 预计时长：60 分钟
- 起始版本：讲师分配的 T01 网页教学分支；`s2-t01-start` 仅用于无网页的离线测试恢复
- 工作目录规则：使用讲师分配的完整仓库目录和唯一小组分支；不使用 Git subtree 或嵌套 worktree 作为 Work Item 目录隔离
- 主训练：证据驱动诊断、失败测试、最小修复、AI 输出审核

## 2. 业务背景

出库单创建后会预占指定库位的库存。如果客户在真正出库前取消，系统应将预占量释放回可用库存，使其他出库单可继续使用。

**业务问题：** 在仓库已经为客户订单预占库存、但货物尚未实际出库的场景下，客服取消了出库单。系统虽然把单据改成了“已取消”，却没有把预占数量释放回可用库存，导致后续订单看到的可用量偏低、无法继续分配。需要定位状态变更与库存释放不一致的根因，在不改变接口和其他出库规则的前提下完成最小修复，使取消操作成功时单据与库存同时生效，库存释放失败时两者同时回滚。

## 3. 业务报障原文

> 单号 SO-101 先预占了 6 件库存，客户取消后单据已显示“已取消”，但库存页面仍显示 6 件被预占，可用库存没有恢复。请尽快修复。

以上是现象，不是根因。不允许仅根据报障文字让 AI 直接改代码。报障中的 `SO-101` 是业务示例；课堂取证时记录页面已有单据的真实单号和 SKU，不要求重新制造一个相同编号的单据。

## 4. 已知材料和环境

- 自动化测试数据：仓库 `1`、库位 `1`、SKU `101`；网页预置记录的单号和 SKU 以页面实际显示为准。
- 页面已经存在一笔完成取消的 T01 出库单；不要新增出库单，不要重新预占或再次取消。
- 页面观察：在出库订单列表选择已有的 `CANCELLED` 单据，进入库存明细并刷新。
- 前置业务事实：取消前总库存为 10，该单据预占了 6；这些前置动作由课堂初始场景提供。
- 预期结果：取消后可用量 `10`，预占量 `0`。
- 实际结果：出库单为 `CANCELLED`，可用量 `4`，预占量 `6`。
- 现有接口示例：`docs/api-examples.http`。
- 构建和测试统一在 Docker 课堂环境执行，不使用本机 Java/Maven。

网页结果是当前失败事实，不是根因，也不是可重复回归证据。后续由 Agent 运行自动化测试、读取代码并定位原因；学员不需要人工翻代码寻找目标类或方法。

## 9. 必须覆盖的验收场景

1. 取消 `RESERVED` 出库单：单据变为 `CANCELLED`，预占量归零，可用量恢复。
2. 库存释放失败：单据状态不得单独提交。
3. 原有的入库幂等、库存不足回滚和操作人检查仍然通过。
4. 修复不改变 API 请求和响应格式。
