> 用途：现行 T01—T06 任务导航和覆盖关系的唯一入口。  
> 对象：讲师、学员、技术中台、UI、事业部和 QA。  
> 限制：本目录不替代单任务卡、已批准 Spec、代码标签或实际测试结果；状态变化必须同步本表并提供可验证依据。

## 1. 文档定位

本文档是 `training-wms` 所有课堂任务的唯一目录。它先确认“教什么”，再逐张设计“怎么教”。

六张任务卡不按 Java 知识点分类，而按研发人员使用 AI Coding 的真实工作类型分类。并发、幂等、事务、审计和测试是每张卡的审核维度，不单独拆成脱离业务的技术题。

## 4. 统一交付链路

每张任务卡都必须留下以下可追溯链路：

```text
原始输入
  → /grill-with-docs：澄清、项目证据、术语与决定
  → 人工需求准入
  → /to-spec：规格（跨会话任务）
  → 四方评审并批准 Spec（需求、设计、验收、批准记录）
  → /to-tickets：可验证任务（大型任务）
  → /implement：代码、测试与差异
  → /code-review：对照已批准 Spec 和仓库规则审核
  → Spec—代码—测试—结果逐条比对
  → 人工裁决、剩余风险和交付证据
```

禁止以“AI 已执行成功”代替测试报告、差异评审和需求验收。

路径按规模裁剪：T01 可使用轻量 Spec 并跳过 Tickets；T02/T05 可在 Spec 批准后跳过 Tickets；T03/T04/T06 使用完整链路，其中 T06 是全链路考核。路径可以裁剪，但人工批准、Spec 版本、代码差异起点和交付比对不可省略。
