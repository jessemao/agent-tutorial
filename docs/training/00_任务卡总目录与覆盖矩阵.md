# AI Coding 实操任务卡总目录与覆盖矩阵

> 用途：现行 T01—T06 任务导航和覆盖关系的唯一入口。  
> 对象：讲师、学员、技术中台、UI、事业部和 QA。  
> 限制：本目录不替代单任务卡、已批准 Spec、代码标签或实际测试结果；状态变化必须同步本表并提供可验证依据。

## 1. 文档定位

本文档是 `training-wms` 所有课堂任务的唯一目录。它先确认“教什么”，再逐张设计“怎么教”。

六张任务卡不按 Java 知识点分类，而按研发人员使用 AI Coding 的真实工作类型分类。并发、幂等、事务、审计和测试是每张卡的审核维度，不单独拆成脱离业务的技术题。

## 4. 同一治理闭环，不同任务路径

M1 建边界、M3 实施、M4 验证和人工放行不能省略；M2 根据任务复杂度选择是否生成 Spec 和 Tickets。禁止把一条固定 Skill 链机械套给全部任务。

| 任务 | 主路径 | Spec / Tickets 规则 |
| --- | --- | --- |
| T01 Bug | 失败事实 → Agent 自主调查并生成 `01_analysis.md` → 分析与范围批准 → `/implement` + TDD → `/code-review` → 人工合并 | 默认不建 Spec，不建 Tickets；任务卡和失败事实作为需求依据。发现新规则、跨模块影响或契约/事务变化时升级完整路径 |
| T02 需求调整 | `/grill-with-docs` → `/to-spec` → 人工批准 → 单切片 `/implement` → `/code-review` | 必须有 Spec；一个上下文可安全交付时可不建 Tickets，并记录理由 |
| T03 从 0 新建 | `/init-work-item` → `/grill-with-docs` → `/codebase-design` → `/to-spec` → `/to-tickets` → 逐票 `/implement` + TDD → 验证 → `/code-review` → 人工 Decision | 使用完整 Spec / Design / Tickets 路径；Agent 输入采用学员卡定义的单行命令 |
| T04 业务重构 | `improve-codebase-architecture` → 人工选定候选 → `grilling` + `codebase-design` → `/to-spec` → Expand–Migrate–Contract Tickets → `/implement` → `/code-review` | 必须先固定外部行为，再使用完整路径 |
| T05 组件/Skill 复用 | `work-item-*` 编排项目阶段，AI Hero Skills 执行专业动作 | 是否建 Spec / Tickets 由被封装任务决定；不得用项目 Skill 绕过批准 |
| T06 综合考核 | 学员根据有限信息自行选择 Skills 和路径 | 预期识别为复杂、高风险新需求，使用完整 Spec / Design / Tickets 路径 |

所有路径最终都必须留下任务事实、批准后的修改范围、测试证据、双轴 Review、人工 Decision 和 MR/PR 合并记录。禁止以“AI 已执行成功”代替真实测试、差异评审和需求验收。

## 6. 变更规则

1. 新增、删除或替换任务前，必须先更新本矩阵。
2. 新任务入口统一使用 `docs/ai-governance/templates/task-card.md`，后续产物使用同目录对应模板。
3. 未通过学员版和讲师版评审前，不制作故障代码。
4. S0 正确母版不得被课堂故障修改污染。

## T01—T03 测试与 QA 交接口径

开发仅提交当前任务的 TDD 与必要回归（`02_verification.md`）；代码评审记录于 `03_review.md`。测试团队的工程师独立执行功能、页面/API、异常和回归验证，结果写入 `functional-test.md`；另一团队的 QA 审核规范、需求追溯、覆盖、证据和缺陷闭环，结论写入 `qa-review.md`。业务所有者另行验收，交付负责人在 `04_decision.md` 记录最终裁决。不能用开发全绿替代独立测试，不能用 QA 审核替代业务验收。

各阶段分别记录对象版本、具名负责人及团队、待确认事项、状态、结论时间与证据。测试工程师与 QA 不得由同一人员兼任；缺少负责人由讲师/交付负责人指定，未执行保持待执行，未确认保持待确认，不预填 PASS。修复后先更新开发证据，再由测试工程师重测，QA 审核新证据，必要时重新业务验收。

T01 仍按完整手写 Prompt 操作；职责分离不意味着引入预置 Skill。T02/T03 保留各自命令入口。操作与模板以对应学员卡及 `docs/ai-governance/roles-and-approvals.md` 为准。
