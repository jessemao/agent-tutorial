# 任务卡 B：UI 驳回与状态保护

## 1. 验收目标

验证已提交的盘点可被驳回，驳回后不产生差异调整流水，刷新后仍保持 `REJECTED`。

## 2. 角色与对象

- 操作者：测试工程师。
- 见证人：开发负责人。
- 候选对象：与任务卡 A 同一候选提交，但使用重建后的干净运行环境。

## 3. 前置数据

- 仓库：`1`；货位：`1`；SKU：`303`。
- 初始可用量：`10`；实盘量：`9`。
- 本场景开始前执行 `./scripts/classroom-down.sh` 和 `./scripts/classroom-up.sh`。

## 4. 操作步骤

1. 进入“仓储管理 → 库存盘点”，将实盘量设为 `9`。
2. 依次点击“创建盘点”、“确认实盘”和“提交”，核对状态为 `SUBMITTED`。
3. 点击“驳回”，核对状态为 `REJECTED`。
4. 确认页面未显示调整流水。
5. 点击“刷新”，再次核对 `REJECTED` 且无调整流水。

## 5. 通过条件

- [ ] 驳回只能在页面显示可执行时操作。
- [ ] 状态为 `REJECTED`，不进入 `ADJUSTED`。
- [ ] 页面没有调整流水结果。
- [ ] 刷新查询后驳回状态不丢失。
- [ ] 候选提交、环境和实际结果已记录。
