# T06 库存盘点与差异调整：学员任务卡

## 任务定位

- 研发场景：综合考核
- 预计时长：120 分钟
- 起始版本：`scenario/t06-start` / `s2-t06-start`
- 必用能力：AIHero五步Skills、三个人工审核门、自动化验收

## 业务问题

在仓库定期盘点或发现账实不符的场景下，仓管员需要登记某个 SKU、仓库和库位的实盘总量，负责人审核差异后再修正系统库存。盘点期间仍可能发生入库、预占或出库，因此如果直接用实盘数覆盖库存，可能冲掉已预占数量、基于过期快照调整，或因重复审批多次记账。需要建立“创建盘点单记录快照、审批时校验并调整”的完整流程，使差异调整可审核、可追溯、可幂等，并在库存已变化或实盘数小于预占量时安全拒绝。

## 原始需求

> 新增库存盘点，支持根据实盘数修正系统库存。

不允许直接据此编码。小组必须完整运行：

```text
/grill-with-docs → 人工需求确认 → /to-spec → 需求/设计评审
→ 批准 Spec → /to-tickets → /implement → /code-review → 人工交付裁决
```

`/grill-with-docs`阶段必须完成事实/假设/未知项、跨团队澄清和实施准入判定；`/to-spec`只能记录已经确认的决定，不得自行补齐业务语义。进入实施前必须明确批准的 Spec 路径和版本，记录批准人与时间，并固定代码起点。

## 讲师确认后采用的训练规则

1. 一张盘点单只覆盖一个 SKU + 仓库 + 库位。
2. 实盘数是该维度的物理总量，即可用量 + 预占量。
3. 创建盘点单只记录快照，不立即改库存；本训练不冻结出入库。
4. 审批时才调整；必须锁定库存并确认当前总量和预占量与快照一致，否则以“陈旧快照冲突”拒绝并要求重盘。
5. 只允许对已存在的库存维度创建盘点单；创建时即校验实盘数不得小于预占量。审批调整只改可用量，不改预占量。
6. 审批成功必须产生一条 `COUNT_ADJUST` 库存流水和审计事件。
7. 相同幂等键重试返回原结果；不同键对已审批盘点单操作必须报冲突。

## 所有权与修改边界

- 允许：`business-wms` 的盘点、库存公开入口和 Web API；`training-server` 的集成测试。
- 只读复用：`platform-contracts`、`platform-web-starter`和 `.agents/skills`。
- 禁止：为完成仓储需求修改平台契约/实现、改动旧 API、删除旧测试。
- UI 团队只需确认请求/响应契约，本任务不实现页面。

## 必须覆盖的自动化场景

- 创建盘点单不改库存，审批后正确盈/亏调整。
- 不存在的库存维度在创建时拒绝。
- 实盘数小于预占量时拒绝且不改库存。
- 创建后库存变化，审批时以陈旧快照冲突拒绝，且盘点单不得误标已审批。
- 相同幂等键安全重放，不同键冲突。
- 原 11 条业务测试与 3 条平台契约测试保持通过。
