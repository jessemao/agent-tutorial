# 离线AI演示与恢复包

> 用途：网络、AI 服务或现场环境异常时维持课程目标。  
> 限制：预置输出只用于教学对照，不是当前 Agent 真实运行证据；服务恢复后必须使用同一输入补跑并重新人工裁决。

> 版本：V0.7  
> 适用：AI服务不可用、网络异常、输出偏离、依赖无法下载或讲师环境污染。  
> 原则：本包用于保持教学链路，不用预置答案伪装学员独立完成。

本目录属于讲师恢复材料，不进入 T06 学员起始分发包。只有完成 G1 问题建模和必要的规则确认后，讲师才能按故障场景投放对应的预置片段。

## 1. 包内容

| 文件 | 用途 | 使用时机 |
|---|---|---|
| `01_固定演示输入.md` | 需求审核、错误方案、代码评审的固定输入 | AI演示开始前 |
| `02_需求审核标准输出.md` | `/grill-with-docs` 阶段的离线 Review 示例 | AI越过需求门或服务不可用 |
| `03_典型错误AI方案与Diff.md` | 用于识别需求、所有权、事务和测试问题的负例 | AI实施演示偏离或无AI |
| `04_代码评审标准输出.md` | `/code-review` 的 Spec/Standards 双轴评审示例 | 代码评审环节 |
| `05_人工裁决示例.md` | 对AI建议做接受、拒绝、修改后接受和待确认 | 每次AI演示收口 |
| `06_T01-T06离线恢复索引.md` | 标签、信号、学员产物和答案对照入口 | 任务卡住或环境失败 |
| `07_异常恢复操作卡.md` | 按异常类型执行的讲师/助教操作卡 | 故障现场 |
| `08_断网与无AI演练验收表.md` | 证明离线包可用 | 课前演练和T-5联调 |
| `09_测试全绿但审核不放行_异常演示卡.md` | AIHero首轮实演中发现的真实质量异常 | 讲解“测试通过不等于可以交付” |

## 2. 三个稳定演示

1. **需求审核**：投入一句盘点需求，正确信号是列出未知项并判定`BLOCKED`。
2. **AI实施负例**：审查一份越过需求门、越界改平台、事务不完整的候选方案与Diff。
3. **代码评审**：对固定差异分别做`SPEC`和`STANDARDS`评审，由人工裁决，不以AI结论自动放行。

## 3. 使用标记

投屏或发给学员时，在产物顶部标记：

```text
[预置离线产物]
原因：AI不可用 / 网络不可用 / 现场输出偏离
学员任务：审核、修正、补测试和人工裁决
不代表：学员独立生成或实施完成
```

## 4. 课前复制清单

- 讲师环境保留完整本地 Git 仓库及 `s2/s3` 标签；学员环境只暴露任务起点，不暴露 T06 答案 refs。
- 本目录全部文件。
- 讲师环境保留 T01—T06 学员卡、讲师参考和评分细则；学员分发包只包含学员所需入口。
- AIHero 五步主链路、项目级 Clean Code Skills、治理 Templates 和本目录预置产物。
- 预先成功运行过构建的Maven本地依赖缓存或一台已暖机的讲师环境。
- 可离线打开的文本编辑器、终端和HTTP请求工具。

## 5. 保密与完整性

- 不将真实客户需求、密钥、账号、Cookie或完整AI对话导出物放入包中。
- 负例Diff仅用于评审，不应用到正确分支。
- 答案标签只用于讲师对照和恢复，不覆盖学员差异。
- 每次使用离线产物都在助教记录中注明原因、时间、受影响小组和课后补验计划。
