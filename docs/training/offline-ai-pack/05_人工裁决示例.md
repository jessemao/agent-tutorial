# 人工裁决示例

> 状态：课堂示例，不是任何小组的正式 Decision。  
> 限制：裁决必须由有权限的人针对当前 Finding 作出，不得由 Agent 复制示例代签。

> 目标：演示AI输出只是输入，不是放行结论。每条意见必须由人根据需求、代码、测试和所有权裁决。

## 1. 裁决表

| AI意见 | 人工结论 | 理由和证据 | 后续动作 |

| 创建盘点不应立即修改库存 | **接受** | T06确认规则3；候选Diff与该规则直接冲突 | 拆分创建和审批，先补“创建不改库存”测试 |

## 2. 四句收口示例

1. **AI已经做了什么**：它按SPEC和STANDARDS找到了6个可操作问题，并给出了最小修正建议。
2. **哪些只是AI声明**：它建议的HTTP 422、流程引擎和库位冻结不是已确认需求，不能直接实施。
3. **人工验证了什么**：已对照T06规则、AGENTS.md、架构文档和UI契约，接受需求和所有权问题，拒绝越范围方案。
4. **还剩什么风险**：候选Diff尚不可执行；单号冲突映射、生产权限和审计持久化尚需后续证据。

## 3. 学员产物要求

学员不能复制本表作为自己的裁决，必须至少对三条AI意见分别给出：

- 原AI意见。
- 接受/拒绝/修改后接受/待确认。
- 需求、代码、测试或所有权证据。
- 需要修改的文件或需要确认的所有者。
