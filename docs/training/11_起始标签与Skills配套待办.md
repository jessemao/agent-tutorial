## 2. TODO-01：重建课堂起始点

### 2.1 目标

每个 `s2-t0x-start` 都应同时具备：

- 与任务匹配的业务起始代码和故意保留的问题/能力缺口；
- 当前根 `AGENTS.md`、Module `AGENTS.md`；
- 当前 `docs/ai-governance/`、Templates、Standards 和自动校验脚本；
- 当前任务需要的 `.agents/skills/` 和对应 `skills-lock.json`；
- 对应课堂页面、Docker 启动方式和起点测试；
- 不包含当前任务答案、Work Item、答案证据或后续任务实现。

### 2.2 各任务最低 Skill 要求

| 任务 | 起始点必须可用的 Skills | 特别限制 |
| --- | --- | --- |
| T01 | `implement`、`tdd`、`code-review`、`clean-*` | 默认不需要独立 Spec/Tickets |
| T02 | `grill-with-docs`、`to-spec`、`implement`、`code-review`、`codebase-design` | `codebase-design` 仅在 Interface/Seam 不清时使用 |
| T03 | `grill-with-docs`、`domain-modeling`、`codebase-design`、`to-spec`、`to-tickets`、`implement`、`tdd`、`code-review` | 不能在起点泄露业务裁决和参考设计 |
| T04 | `improve-codebase-architecture`、`grilling`、`codebase-design`、`to-spec`、`to-tickets`、`implement`、`code-review` | 必须保留重构前公开行为和旧调用方 |

1. 先从当前治理材料形成候选课程起点提交，不移动现有标签。

5. 保存旧标签提交号和恢复说明后，再由人工批准更新标签。
6. 标签更新后重新构建课堂镜像，并记录镜像摘要与标签提交。

## 6. TODO-05：最终全局清理

### 6.1 清理范围

- 旧“基线”或 `baseline` 表述：统一改为“课堂起点”“批准后的 Spec/规则”或实际含义；代码中的合法领域名必须先人工确认，不能机械替换。
- 旧 Skill 链：清理已经被 AI Hero 主链或新版项目治理 Skills 取代的调用说明、旧 Prompt 和旧 Skill 名；需要保留的历史示例必须明确标记“仅供历史对照”。
- 失效 Tag：检查是否能解析、是否包含正确任务起点/答案、是否与文档引用一致；删除或移动任何 Tag 前必须保存提交号并获得人工批准。
- 重复入口：课程 README、学员入口、任务总目录、讲师材料入口和离线恢复索引各自只承担一种职责，不得存在两个互相冲突的“唯一入口”。
- 重复真相：相同规则只在权威治理文档中定义，任务卡和讲师稿只引用或说明任务特例。

### 6.2 处理步骤

1. 全仓搜索旧术语、旧 Skill 名、Tag 引用、旧 Prompt、重复标题和重复导航。
2. 建立“保留、替换、归档、删除”清单；先处理引用，再处理被引用对象。
3. 对 Git Tag 做解析、内容和任务语义检查，记录当前提交号；未经批准不移动或删除 Tag。
4. 统一导航：根 README 指向项目文档，培训入口指向任务目录，讲师入口指向授课脚本，离线索引只负责恢复。
5. 删除或归档重复材料后重新执行 Markdown 链接、治理门禁、Skill 哈希、Tag、Docker 和分发包检查。
6. 用学员身份和讲师身份分别从唯一入口走读一遍，确认不会进入旧流程或看到越权材料。

### 6.3 验收条件

- [ ] 全仓没有未解释的“基线”/`baseline` 旧表述；允许项有明确白名单和理由。
- [ ] 学员材料中没有旧 Skill 链、废弃 Prompt 或不存在的 Skill 调用。
- [ ] 所有被引用 Tag 均可解析并指向正确内容；失效或重复 Tag 已经人工批准后处理。
- [ ] 根 README、培训总目录、学员入口、讲师入口和离线恢复索引之间没有职责冲突。
- [ ] 不存在两份同时声称权威、但内容不同的治理规则或任务入口。
- [ ] Markdown 链接、治理校验、Skills 哈希、Docker 启动和材料分发检查全部通过。
- [ ] 清理结果保存变更清单和恢复方式，删除内容仍可通过已记录提交追溯。
