# T03 从零新建同仓库库内移库：讲师参考

> 对象：讲师/助教。状态：与 `s2-t03-start` / `s3-t03-answer` 配套。  
> 投放限制：领域决定和锁顺序应在学员完成问题清单后分阶段释放，答案只用于对照评审。

## 设计意图

观察学员是否会把一句业务口号直接交给 AI，还是先把库存维度、不变式、事务、幂等和并发问题变成可测试规则。

## 120 分钟投放

| 阶段 | 时间 | 产物 |
| --- | ---: | --- |
| 原始需求审核 | 0—25 | 澄清清单与裁决 |
| 领域与契约 | 25—50 | 命令、结果、API 和影响面 |
| 测试先行 | 50—70 | 验收矩阵与测试骨架 |
| AI 实施 | 70—105 | 核心路径代码 |
| 评审复盘 | 105—120 | Diff 评审和并发风险 |

## 标准方案

- `InventoryTransferCommand` 表达一次完整移库。
- `InventoryOperations.transfer()` 是唯一公开修改入口。
- 先用 `TRANSFER_OUT/TRANSFER_IN + idempotencyKey` 查重。
- 两库位按 ID 升序加锁，验证启用状态和仓库归属。
- 来源余额必须存在，目标余额可创建。
- 来源扣减、目标增加、两条流水和审计为同一事务。

## AI 常见错误

- 用出库和入库两个 HTTP 请求串联。
- 先创建目标并捕获来源失败。
- 直接修改 available 字段，绕过不变式。
- 只锁来源，或按请求顺序锁 A/B。
- 将仓储移库规则放入平台模块。

## 验收矩阵

| 场景 | 期望 |
| --- | --- |
| 正常移库 | 源减、目标增、总量不变 |
| 相同请求重试 | 返回原结果 |
| 冲突幂等载荷 | `WMS_IDEMPOTENCY_CONFLICT` |
| 来源不足 | 整体回滚 |
| 同库位或非法库位 | 拒绝 |
| 目标无余额 | 原子创建并增加 |
| 缺少操作人 | 整体回滚 |

## 已知剩余风险

H2 测试已验证业务事务和幂等，但“两个并发事务同时首次创建同一目标余额”仍依赖唯一约束解决竞争。生产方案应评估可控重试，课堂不将它包装成已完成能力。

## T01—T03 测试与 QA 交接口径

开发仅提交当前任务的 TDD 与必要回归（`02_verification.md`）；代码评审记录于 `03_review.md`。测试团队的工程师独立执行功能、页面/API、异常和回归验证，结果写入 `functional-test.md`；另一团队的 QA 审核规范、需求追溯、覆盖、证据和缺陷闭环，结论写入 `qa-review.md`。业务所有者另行验收，交付负责人在 `04_decision.md` 记录最终裁决。不能用开发全绿替代独立测试，不能用 QA 审核替代业务验收。

各阶段分别记录对象版本、具名负责人及团队、待确认事项、状态、结论时间与证据。测试工程师与 QA 不得由同一人员兼任；缺少负责人由讲师/交付负责人指定，未执行保持待执行，未确认保持待确认，不预填 PASS。修复后先更新开发证据，再由测试工程师重测，QA 审核新证据，必要时重新业务验收。

T01 仍按完整手写 Prompt 操作；职责分离不意味着引入预置 Skill。T02/T03 保留各自命令入口。操作与模板以对应学员卡及 `docs/ai-governance/roles-and-approvals.md` 为准。
