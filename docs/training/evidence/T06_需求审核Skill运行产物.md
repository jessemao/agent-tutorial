# T06 需求审核 Skill 运行产物

## Original request

“新增库存盘点，支持根据实盘数修正系统库存。”

## Facts and evidence

- 库存维度为 SKU + 仓库 + 库位：`InventoryBalance`。
- 系统分开保存可用量和预占量：`InventoryBalance`。
- 所有库存修改应通过 `InventoryOperations`：接口文档和 T04 结论。
- 幂等、审计和统一错误组件可复用：T05 答案版本及 3 条契约测试。

## Assumptions

原始需求不足以实施；本文不自行填充规则，待下列问题由讲师代表业务、平台和UI回答后再转为验收条件。

## Unknowns and questions by owner

- 业务：盘点范围是单库位还是仓库？实盘数是物理总量还是可用量？盈亏是否都允许？
- 业务：是否审批？谁能审批？创建后库存变化怎么办？
- 业务/平台：盘点期间是否冻结出入库？并发冲突如何表达？
- 业务：实盘小于已预占量如何处理？
- 业务/合规：调整流水、原因、审批人和审计要求是什么？
- UI：创建、审批和冲突提示需要哪些字段？

## Proposed acceptance criteria

详见学员任务卡的7条“讲师确认后规则”和5类必须自动化场景；确认前均为提案。

## Impact, ownership, and boundaries

- 仓储事业部：盘点领域、库存调整入口、API，允许修改。
- 公共研发中心：现有平台契约和实现，只读复用。
- UI 团队：确认 API 字段和错误展示，本任务不实现页面。
- 培训组：集成测试和演示组装。

## Non-goals

- 多 SKU/整仓盘点、盲盘/复盘、批次和序列号。
- 通用审批流程引擎、权限中心改造和 UI 页面。
- 生产级长时间库位冻结。
