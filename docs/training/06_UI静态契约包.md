# UI静态契约包

> 用途：供 UI、技术中台、事业部和 QA 在训练中统一字段、状态、错误和兼容含义。  
> 状态：课程静态契约，不是生产 API 或公司级 UI 标准。  
> 限制：未经 UI/契约所有者确认、且未经开发负责人批准实施范围，不得据此修改公开契约；代码和本文冲突时必须记录并裁决，不能由 Agent 自行选择。

> 用途：不建设完整前端工程，用一组可审核契约模拟UI团队、技术中台和仓储事业部的真实协作。  
> 代码证据：`ApiResponse`、`GlobalExceptionHandler`、`ShipmentStatus`、`StocktakeStatus`以及对应Web DTO。

## 1. 所有权与变更规则

| 契约 | 所有者 | 事业部可做 | 事业部不可做 | 变更必须附带 |
|---|---|---|---|---|
| 响应包装 | 技术中台 | 返回`ApiResponse<T>` | 自建另一套成功/失败结构 | 平台评审、兼容结论、契约测试 |
| HTTP错误映射 | 技术中台 | 抛出有稳定代码的业务异常 | 在Controller里散落组装错误响应 | 错误码影响清单、回归测试 |
| 页面与组件规范 | UI团队 | 按开放点配置业务字段 | 改变公司级状态、错误展示和无障碍规则 | UI评审、新旧效果、迁移说明 |
| 仓储字段与状态 | 仓储事业部 | 维护业务含义和后端状态机 | 未通知UI直接重命名/删除字段或枚举 | 需求审核、API差异、UI影响和测试 |

## 2. 统一响应契约

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 规则 | UI处理 |
|---|---|---|---|
| `success` | boolean | 业务是否成功 | 不得只以HTTP 200判断成功 |
| `code` | string | 稳定、可用于分支；成功为`OK` | 程序逻辑使用`code`，不解析`message` |
| `message` | string | 给人的说明，可变 | 可作默认提示，不作状态判断 |
| `data` | object/null | 成功时为业务数据，失败时为`null` | 失败时不读取业务字段 |

HTTP约定：参数校验失败返回400 + `INVALID_REQUEST`；当前业务异常统一返回409 + 具体业务错误码。调整HTTP映射属于平台契约变更。

## 3. 状态契约

### 3.1 出库单

| 后端值 | UI文案 | 可用操作 | 禁用操作 |
|---|---|---|---|
| `CREATED` | 已创建 | 预占、取消 | 出库 |
| `RESERVED` | 已预占 | 出库、取消 | 再次预占 |
| `SHIPPED` | 已出库 | 查看 | 预占、出库、取消 |
| `CANCELLED` | 已取消 | 查看 | 预占、出库、再次取消 |

`cancelReason`在非取消状态可为`null`；取消后UI展示实际原因。UI的按钮禁用只是交互提示，后端必须仍验证状态。

### 3.2 入库单（T02 训练契约，代码待同步）

| 后端值 | UI文案 | 可用操作 | 说明 |
|---|---|---|---|
| `CREATED` | 待收货 | 收货、查看 | 尚未发生收货 |
| `PARTIALLY_RECEIVED` | 部分收货 | 继续收货、查看 | 展示计划量、累计实收和剩余量 |
| `RECEIVED` | 已收货 | 查看 | 累计实收等于计划量，不再允许收货 |

### 3.3 盘点单

| 后端值 | UI文案 | 可用操作 | 说明 |
|---|---|---|---|
| `PENDING_APPROVAL` | 待审批 | 审批、查看 | 创建只记录快照，不改库存 |
| `APPROVED` | 已审批 | 查看 | 不允许以不同幂等键重复审批 |

UI不得自行推导盘点单已生效，只以服务端返回的`status` 为准。

## 4. 核心字段契约

| 对象 | 字段 | 规则 | UI校验/展示 |
|---|---|---|---|
| 库存 | `skuId`,`warehouseId`,`locationId` | 共同定位一条库存 | 必填，不用展示名称反向作为ID |
| 库存 | `availableQuantity`,`reservedQuantity` | 均不得为负 | 分开展示，不将可用量当作物理总量 |
| 入库 | `plannedQuantity`,`receivedQuantity` | 计划量与累计实收量 | 同时展示剩余量，不把本次数量覆盖累计量 |
| 入库收货 | `receivedQuantity` | T02 中表示本次实收量，必须为正 | 提交前展示“本次收货”，不得标成累计数量 |
| 出库 | `orderNo` | 业务单号 | 必填；唯一冲突以后端结果为准 |
| 取消 | `idempotencyKey` | 一次用户意图的稳定键 | 重试必须复用原键，不每次点击都重生成 |
| 取消 | `reason` | 按出库取消契约审核是否必填 | 前端校验不代替后端校验 |
| 盘点 | `countNo` | 盘点单号 | 必填；不默认承诺客户端唯一性判断 |
| 盘点 | `countedTotalQuantity` | 物理实盘总量，非可用量 | 非负整数；低于预占量时显示业务错误 |

## 5. 错误展示契约

| 错误码 | UI分类 | 建议处理 |
|---|---|---|
| `INVALID_REQUEST` | 输入错误 | 页内/字段级提示；保留用户输入 |
| `WMS_SHIPMENT_STATE` | 状态冲突 | 刷新出库单状态，禁用已不可用操作 |
| `WMS_INSUFFICIENT_AVAILABLE` | 库存不足 | 展示业务错误并刷新库存 |
| `WMS_INSUFFICIENT_RESERVED` | 预占不足 | 展示业务错误并刷新库存/单据 |
| `WMS_INVENTORY_OVERFLOW` | 数量超出可表示范围 | 保留输入并提示调整数量；失败不改变库存。2026-08-31课程修复新增，沿用409包装，企业发布前须UI/业务确认 |
| `WMS_IDEMPOTENCY_CONFLICT` | 重复操作冲突 | 停止自动重试，查询最新状态 |
| `WMS_COUNT_BELOW_RESERVED` | 盘点规则冲突 | 保留实盘输入，提示人工核对预占 |
| `WMS_COUNT_SNAPSHOT_STALE` | 并发/快照过期 | 不自动重提审批；刷新并重新盘点 |
| `WMS_*_NOT_FOUND` | 资源不存在 | 回到列表或刷新，不反复弹窗 |
| 未知代码 | 未知异常 | 统一降级提示并保留`code`用于排查，不向用户展示堆栈 |

## 6. 兼容性检查表

任何Agent修改API、DTO、状态或错误码前，必须回答：

1. 是新增可选字段，还是重命名/删除/改类型？
2. 现有UI遇到新状态时会降级还是失效？
3. 是否改变HTTP状态、`success`或`code`的语义？
4. 旧客户端重试时，幂等键是否仍有效？
5. 字段校验、状态按钮和错误展示是否需要同步更新？
6. 是否已有契约测试或接口回归证据？

## 7. 课堂用法

- T02：检查分批收货新增状态、数量字段、继续收货按钮、超收错误和旧客户端兼容性。
- T04：验证业务重构前后API、状态和错误可观察行为不变。
- T05：判断响应包装和错误处理属于平台能力，事业部不得复制。
- T06：审核盘点状态、快照过期和幂等冲突的UI处理，将契约结论加入交付证据。

## 8. 验收标准

- 学员能准确指出平台、UI和事业部各自拥有的契约。
- 面对API变更，学员不只检查后端编译和测试，还能输出UI影响。
- Agent不得未经确认直接修改平台响应、错误或UI公司级契约。
- 任何兼容性结论都有API差异、测试或人工确认证据。

## T01—T03 测试与 QA 交接口径

开发仅提交当前任务的 TDD 与必要回归（`02_verification.md`）；代码评审记录于 `03_review.md`。测试团队的工程师独立执行功能、页面/API、异常和回归验证，结果写入 `functional-test.md`；另一团队的 QA 审核规范、需求追溯、覆盖、证据和缺陷闭环，结论写入 `qa-review.md`。业务所有者另行验收，交付负责人在 `04_decision.md` 记录最终裁决。不能用开发全绿替代独立测试，不能用 QA 审核替代业务验收。

各阶段分别记录对象版本、具名负责人及团队、待确认事项、状态、结论时间与证据。测试工程师与 QA 不得由同一人员兼任；缺少负责人由讲师/交付负责人指定，未执行保持待执行，未确认保持待确认，不预填 PASS。修复后先更新开发证据，再由测试工程师重测，QA 审核新证据，必要时重新业务验收。

T01 仍按完整手写 Prompt 操作；职责分离不意味着引入预置 Skill。T02/T03 保留各自命令入口。操作与模板以对应学员卡及 `docs/ai-governance/roles-and-approvals.md` 为准。
