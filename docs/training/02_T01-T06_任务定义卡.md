# T01—T06 任务定义卡

> 用途：固定六类训练任务的业务场景、核心目标和禁止捷径。  
> 状态：现行课程定义；具体输入、分支、验收和停止条件以对应学员任务卡为准。  
> 限制：不得根据本页摘要直接要求 Agent 编码，也不得用讲师答案反推或覆盖学员应完成的发现过程。

## T01 修改 Bug：取消出库单未释放库存

- 业务问题：在出库单已预占但尚未发货时，客户取消订单；系统只取消单据却未释放预占，导致后续订单无法使用这批库存。需要修复为单据与库存同事务成功或回滚。
- 原始输入：业务报障“出库单已取消，可用库存没恢复”。
- 起始状态：提供可稳定复现的故障版，但不告知根因。
- 主训练：区分现象与根因，先写失败测试，进行最小修复。
- 业务核心：只有取消 `RESERVED` 出库单才释放预占量；单据状态和库存修改必须同事务。
- 必做审核：重复取消、回滚、负预占、无关代码改动。
- 禁止快捷做法：在 Controller 里直接改库存；删除失败测试；扩大为全库重构。
- 完成证据：修复前测试失败、修复后通过、原有回归全部通过。

## T02 调整需求：入库单支持分批收货

- 业务问题：供应商分多批到货，仓库要逐批登记本次实收量并立即入账；系统目前只能一次收完。需要支持部分状态、累计收满、超收拒绝、幂等与并发安全，并保护旧调用方。
- 原始输入：入库单必须一次性收完计划数量，成功后增加库存并完成单据。
- 变更输入：允许按“本次实收数量”分多次收货，累计达到计划量后完成。
- 主训练：审核新旧差异，确认数量和状态语义，判断 API/UI/库存/审计影响并保护旧调用方。
- 业务核心：部分收货进入 `PARTIALLY_RECEIVED`；收满进入 `RECEIVED`；超收整体拒绝。
- 必做审核：本次量与累计量、超收、幂等、并发、事务回滚和旧 API 兼容。
- 禁止快捷做法：让 AI 自行选择数量语义；超收静默截断；重试重复入账。
- 当前限制：代码起点和答案标签尚未同步，先完成需求、设计、测试骨架与任务指令。
- 完成证据：新旧差异表、状态转换矩阵、兼容性与回归测试。

## T03 从 0 新建需求：同仓库库内移库

- 业务问题：仓库补货或整理库位时，需要把可用库存从一个库位原子移动到另一个库位；用两次出入库拼接会产生中间失败和流水断裂。需要新增来源、目标、双流水和审计一致提交的移库能力。
- 原始输入：“支持把一个库位的库存移到另一个库位。”
- 起始状态：只有入库、预占、释放和出库，没有移库模型和接口。
- 主训练：从模糊需求产出可实施的领域模型、契约和验收测试。
- 必须澄清：是否允许跨仓、预占量是否可移、部分成功、流水、幂等、并发和权限。
- 默认训练结论：只支持同仓不同库位；只移可用量；来源和目标变更原子提交。
- 禁止快捷做法：复用“出库+入库”两个 HTTP 请求假装原子移库。
- 完成证据：需求澄清单、领域和 API 设计、正反向流水、并发和回滚测试。

## T04 业务重构：统一库存业务入口

- 业务问题：库存能力持续扩展后出现多个修改入口，相同校验、幂等、流水和审计规则开始分散。需要在外部行为不变的条件下统一公开边界，使库存规则只有一个权威归属。
- 原始输入：“库存规则分散，请统一入库、预占、释放、出库和移库入口。”
- 起始状态：功能可用但存在重复规则或越过模块入口的故意代码。
- 主训练：先固化行为再重构，将不变式集中到深模块，保持外部契约不变。
- 必做审核：现有行为清单、依赖方向、事务边界、可见性、旧接口回归。
- 禁止快捷做法：重写整个模块；引入新框架；把所有逻辑放入一个“万能 Service”。
- 完成证据：重构前后同一套契约测试、依赖边界检查和差异说明。

## T05 组件与 Skill 复用：平台沉淀与事业部接入

- 业务问题：多个事业部都需要审计、幂等和 AI 审核流程；各自复制会漂移，全部上收又会污染平台。需要区分通用机制与业务语义，沉淀最小组件和 Skill，并让事业部保留模型与事务决策。
- 原始输入：“其他事业部也需要幂等、审计和 AI 审核流程，请复用仓储实现。”
- 起始状态：仓储模块存在局部实现，平台已有操作人、审计和统一错误契约。
- 主训练：判断哪些是平台共性，哪些必须留在事业部；区分代码组件和 AI Skill。
- 代码交付：最小公共契约、默认适配器和两个事业部差异化接入样例。
- Skill 交付：需求审核和代码评审 Skill，明确触发条件、输入、输出、证据和停止条件。
- 禁止快捷做法：把 SKU、库位等仓储语义放入平台组件；创建一个无边界的“通用业务 Skill”。
- 完成证据：复用决策表、契约测试、事业部接入证据、Skill 实际运行产物。

## T06 综合考核：库存盘点与差异调整

- 业务问题：仓库盘点发现账实差异，需要先记录实盘快照、审批后再调整；盘点期间库存仍可能变化。需要保证调整可审核、可追溯、可幂等，并拒绝过期快照和破坏预占量的操作。
- 原始输入：“新增库存盘点，支持根据实盘数修正系统库存。”
- 起始状态：学员拥有前五个任务形成的正确版本、公共组件和 Skill。
- 主训练：独立完成需求审核、跨团队边界判断、设计、实施、测试、评审与交付。
- 必须澄清：盘点范围、冻结策略、预占量、差异审批、重复调整、流水和审计。
- 默认训练结论：实盘数为物理总量；不得小于已预占量；差异审批后才调整；调整必须幂等。
- 组织方式：小组交付，必须明确需求审核、AI 操作、代码评审和汇报责任人。
- 一票否决：未审需求直接编码；无测试证据；库存不变式被破坏；事业部越权修改平台实现。
- 完成证据：完整追溯链、代码与测试、AI 输出评审、演示和剩余风险。
