# 测试检查引导

> 本文件定义测试入口和证据要求；具体任务测试由 Spec、Module `AGENTS.md` 与测试代码共同决定。

## 测试顺序

1. Bug：先稳定复现红灯，再修复。
2. 新需求：先用测试表达批准后的验收条件。
3. 重构：先保存原行为测试结果，重构后运行同一组测试。
4. 交付：目标测试 → 受影响 Module 回归 → `mvn clean verify`。

## 必须覆盖

- 正常路径与关键状态变化。
- 非法状态、边界值和库存不足。
- 重复请求与幂等。
- 涉及库存写入时的事务回滚。
- 涉及竞争时的并发行为或明确的未覆盖风险。
- 平台公开契约的兼容性。

## 证据要求

每条测试证据记录代码版本、命令、环境、开始/结束时间、通过/失败/跳过数量和原始输出路径。只写“已运行”或复制历史日志不能作为证据。

测试无法表达验收条件、使用了错误代码版本、失败被忽略或跳过原因未批准时，停止交付。
