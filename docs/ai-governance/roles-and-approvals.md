# AI 治理角色与审批权限

> 从 T01 起适用；开发、测试工程师、QA、业务验收分别执行和记录。测试与 QA 是推荐的课堂角色，不是所有企业流程的强制签署人。

## 1. 角色定义

| 角色 | 主要责任 | 边界 |
| --- | --- | --- |
| 开发人员 / 实施 Agent | 按已批准 Ticket 实施，完成任务 TDD 和必要回归，提交开发证据 | 不得伪造测试、QA 或业务结论；企业若采用独立测试/QA，开发自测不能替代它们 |
| 测试工程师 | 独立设计并执行需求级功能测试、页面与接口测试、异常、幂等、并发、回滚、兼容和跨 Ticket 回归 | 不代替开发批准范围，不代替 QA 出具质量审核结论 |
| QA 人员 | 审核流程执行、规范符合性、需求追溯、测试覆盖、证据、缺陷关闭与例外有效性 | 不承担测试工程师的用例执行，不用审核通过代替测试通过 |
| 业务所有者 | 确认场景、规则、非目标，验收业务目标，参与风险裁决 | 不负责手工构造幂等键、并发和故障注入 |
| 开发负责人 | 批准实施目标、设计、代码范围、技术接缝和回滚方案 | 不代签独立测试和 QA 结论 |
| UI/契约所有者 | 确认字段、交互、HTTP/UI 契约与兼容窗口 | 不代改业务规则和事务边界 |
| 技术中台所有者 | 平台、跨 Module 契约、共性能力与技术 Standards | 不代改事业部业务语义 |
| AI 治理所有者 | Workflow、Templates、项目编排、质量门禁与例外台账 | 不代替业务验收 |
| 课程讲师/交付负责人 | 说明课堂建议，组织业务验收和最终交付裁决 | 不伪造测试、QA、业务签字或实际合并结果；允许记录企业自定义流程 |

课堂默认建议测试工程师和 QA 由两套人员独立承担。企业可按自身制度替换或省略其中一个阶段，并在 Work Item 中记录流程名称、责任方、替代证据和风险；若同时启用两者，仍不得合并角色。Agent 可协助整理证据，但不得批准自己的输出或代签。

## 2. 决策权矩阵

| 决策对象 | 责任人 | 输出 |
| --- | --- | --- |
| 业务规则、非目标 | 业务所有者 | Analysis / Spec 的确认记录 |
| UI/API 契约 | UI/契约所有者 | Interface 的确认记录 |
| 实施范围与技术接缝 | 开发负责人，涉及公共边界时征得相关所有者同意 | 实施批准记录 |
| Ticket TDD 完成 | 开发人员提交，开发负责人检查 | `02_verification.md` |
| 独立功能测试（可选） | 测试工程师或企业指定的验收责任方 | `functional-test.md` 或企业测试记录；未采用时为 `N/A` 及理由 |
| Spec / Standards 代码评审 | 独立评审人 / 评审 Agent | `03_review.md` 两轴建议 |
| QA 质量审核（可选） | 独立 QA 人员或企业指定的质量责任方 | `qa-review.md` 或企业质量记录；未采用时为 `N/A` 及理由 |
| 缺测与质量例外 | 对应业务/技术/治理所有者裁决，测试工程师说明缺口，QA 核查记录 | 例外台账及 Decision |
| 业务验收和最终放行 | 业务所有者、交付负责人 | `04_decision.md` |

## 3. 审批证据

每个结论记录任务、角色、人员或团队、对象版本、范围、时间、证据、理由和条件。开发验证、独立测试、QA 审核、业务验收四种结论独立记录；未采用测试/QA 阶段时记录 `N/A`、企业流程和替代证据。“全部通过”不自动填充任何签字。

## 4. 缺席与返工

尚未进入对应阶段时，测试或 QA 人员缺席不阻止已批准开发工作。进入测试或 QA 阶段时，只有所选企业流程要求该角色才必须指定负责人；否则记录 `N/A` 和替代方式即可继续。代码变化后由企业流程指定责任方评估重测范围、检查证据版本；历史结论保留，不能直接套用到新版本。

## 5. 分离职责

测试工程师可以在需求设计时提出可测性意见，QA 可以提前检查流程与标准；这些不改变开发负责人是实施范围批准人的职责。QA 审核引用代码评审，不重复冒充代码评审。最终放行须引用开发证据、业务验收和所选企业流程的测试/质量证据；跳过的阶段明确记录，不以缺少课堂签署自动阻塞。

## 待确认责任路由

从 T01 开始，README 和每份阶段产物均记录待确认内容、对象版本、负责角色或企业流程、人员/团队、状态、结论时间和证据。开发完成由开发负责人确认；测试、QA 可由企业流程指定责任方确认，也可记录 `N/A`；业务验收由业务所有者确认；最终放行由交付负责人确认。缺少人员时不得由 Agent 推测或代签，应记录选择的企业流程、替代证据和风险。若同时使用测试与 QA，仍保持角色分离；角色分离与是否使用 Skill 无关。
