# Module Agent Instructions: training-server

本文件继承仓库根目录 `AGENTS.md`，只规定 `training-server` 的局部边界。

## 1. 模块职责

- 所有者：课程维护团队。
- 作为应用组合根，负责 Spring Boot 启动、平台适配器装配、运行配置、演示数据、课堂静态操作页和端到端测试。
- 本模块不承载仓储业务规则。

## 2. 修改范围

- 可以修改：启动类、Configuration、Profile、演示数据、运行配置、`src/main/resources/static/` 下的课堂静态操作页和集成测试。
- 课堂静态页只能调用已批准的公开 API，不得在页面中复制后端写逻辑、更改数据库或将 UI 判定当作业务真相。
- 不得加入：库存、入库、出库、移库或盘点判断。
- 不得复制 `business-wms` 的规则，也不得通过配置、测试替身或演示数据绕过业务校验。
- 生产、测试和课堂演示配置必须明确隔离。

## 3. 依赖与运行环境

- 本模块可以装配 `business-wms` 及其传递的平台能力，不得形成被业务或平台模块反向依赖的入口。
- 默认测试环境使用 H2；MySQL 验证使用 `mysql-verification` Profile。
- 环境差异不得改变公开业务语义、事务要求或验收条件。
- 配置中不得硬编码密钥、口令或依赖个人机器路径。

## 4. 测试边界

- 集成测试必须通过公开 API 或稳定业务入口验证行为和最终状态。
- 不得直接修改数据库、调用 Repository 或拼装内部实现来制造测试通过。
- 修改装配、Profile、数据库配置或演示数据时，必须验证默认 H2 环境和所有受影响的 MySQL 场景。

## 5. 验证

- 集成验证：`mvn -pl training-server -am test`。
- MySQL 任务按课程环境使用 `mysql-verification` Profile 验证。
- 最终验证：`mvn clean verify`。

## 6. 停止条件

出现以下情况时停止并请求相关所有者裁决：

- 业务规则进入装配层，或测试需要绕过公开入口。
- H2 与 MySQL 的行为差异会影响验收结果。
- Profile、演示数据或运行配置改变了业务语义。
- 运行环境、凭据来源或依赖版本不明确。
